# پیش‌بینی عوارض بعد از سکته قلبی (Myocardial Infarction Complications)

پروژهٔ درس **هوش مصنوعی و کارگاه** — دانشکدهٔ ریاضی و علوم کامپیوتر، دانشگاه صنعتی امیرکبیر (مهر ۱۴۰۵)
استاد درس: دکتر مهدی قطعی — دیتاست: [UCI Myocardial Infarction Complications (id 579)](https://archive.ics.uci.edu/dataset/579/myocardial+infarction+complications)

برای هر بیمار، **در لحظهٔ پذیرش** احتمال سه پیامد پیش‌بینی می‌شود: مرگ در بیمارستان (`LET_IS`)، نارسایی مزمن قلب (`ZSN`) و فیبریلاسیون دهلیزی (`FIBR_PREDS`). تمرکز پروژه روی **اعتبار ارزیابی، کالیبراسیون و تفسیر** است، نه فقط یک عدد بالا.

> نتایج، شرح و نمودارهای هر بخش در نوت‌بوک [`project_results.ipynb`](project_results.ipynb) آمده است. گزارش فارسی LaTeX با `python src/generate_latex.py` ساخته می‌شود.

## 1. صورت مسئله

**هدف:** مدلی که برای هر بیمار، فقط با اطلاعات در دسترس **در لحظهٔ پذیرش**، احتمال وقوع سه پیامد را پیش‌بینی کند. برای هر پیامد یک مدل طبقه‌بندی دودویی جدا ساخته می‌شود.

| پیامد | ستون | شیوع |
|---|---|---|
| مرگ (هر علتی؛ `LET_IS > 0`) | `LET_IS` | حدود ۱۶٪ (۲۷۱ بیمار) |
| نارسایی مزمن قلب | `ZSN` | حدود ۲۳٪ |
| فیبریلاسیون دهلیزی | `FIBR_PREDS` | حدود ۱۰٪ |

**چهار بعد ارزیابی:** ۱) شناسایی موارد مثبت (AUPRC)، ۲) اعتبار احتمال‌ها (کالیبراسیون)، ۳) ارزیابی معتبر بدون نشت اطلاعات، ۴) تفسیر مدل. معیار اصلی انتخاب مدل **AUPRC** است و *accuracy* معیار اصلی پذیرفته نمی‌شود (مدلی که برای همه «فوت نمی‌کند» بگوید ≈ ۸۴٪ دقت دارد و بی‌ارزش است).

**قوانین سخت پروژه**

- ستون `ID`، هر ۱۲ ستون پیامد و ۹ ستون ممنوع سناریوی پذیرش (`R_AB_1..3_n`، `NA_R_1..3_n`، `NOT_NA_1..3_n`) از ورودی حذف شوند؛ استفاده از یک پیامد برای پیش‌بینی پیامد دیگر ممنوع است.
- ۲۰٪ داده (≈ ۳۴۰ بیمار) با `stratify` روی مرگ و `random_state` ثابت به‌عنوان آزمون جدا و **قفل** شود و فقط یک‌بار در پایان استفاده شود.
- مقایسه و تنظیم روی ۸۰٪ باقی‌مانده با `StratifiedKFold(5)`؛ گزارش میانگین ± انحراف معیار.
- **هر مرحلهٔ یادگرفته‌شده** (جایگذاری، مقیاس‌دهی، انتخاب ویژگی، SMOTE/undersampling) باید داخل `Pipeline` باشد (مهم‌ترین قانون).
- سه مدل اجباری برای هر سه پیامد: مدل پایهٔ شیوع (`DummyClassifier`)، رگرسیون لجستیک، مدل درختی تجمیعی.
- کالیبراسیون پلات اجباری؛ آستانهٔ تصمیم مستدل؛ SHAP برای مرگ؛ پاسخ به ۴ سؤال اجباری و ۲ سؤال یک مقاله؛ بخش امتیازی اختیاری.

**تحویلی‌ها:** فایل CSV احتمال‌ها روی آزمون، کد قابل اجرا، گزارش (روش، جدول CV، نتایج آزمون و ماتریس درهم‌ریختگی، نمودار کالیبراسیون قبل/بعد، SHAP، پاسخ سؤالات).

## 2. دیتاست

- ۱۷۰۰ بیمار، ۱۱۱ ویژگی ورودی (ستون‌های ۲ تا ۱۱۲)، ۱۲ متغیر هدف (ستون‌های ۱۱۳ تا ۱۲۴)؛ بیمارستان بالینی شمارهٔ ۲۰ کراسنویارسک، روسیه، ۱۹۹۲–۱۹۹۵.
- ۸٫۴۷٪ سلول‌ها گمشده‌اند. ۴ ستون با گمشدگی بالای ۵۰٪ در دادهٔ آموزش حذف می‌شوند: `IBS_NASL`، `S_AD_KBRIG`، `D_AD_KBRIG`، `KFK_BLOOD`.
- پس از حذف ستون‌های ممنوع و پرگمشده، حدود ۹۸ ویژگی دودویی/ترتیبی/پیوسته باقی می‌ماند (فهرست و نوع هر ستون: `outputs/metrics/selected_feature_type_profile.csv`).
- فایل خام را از UCI دانلود کنید و در `data/raw/MI.data` بگذارید (در گیت ignore شده است).

## 4. نصب و اجرا

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows  |  source .venv/bin/activate در Linux/macOS
python -m pip install -r requirements.txt
```

فایل `MI.data` را در `data/raw/` بگذارید، سپس:

```bash
python run_all.py            # اجرای کامل
python run_all.py --fast     # اجرای سریع برای تست (جستجوی کوچک‌تر)
python run_all.py --from calibrate_models.py   # ادامه از یک مرحله
```

اجرای کامل روی CPU چندهسته‌ای حدود ۱۰ تا ۳۰ دقیقه است. متغیرهای محیطی: `MI_N_ITER` (تعداد نمونه‌های جستجو، پیش‌فرض ۲۵)، `MI_N_BOOT` (۱۰۰۰)، `MI_N_REPEATS` (۵)، `MI_N_JOBS`، `MI_CALIBRATION` (`sigmoid` پیش‌فرض یا `isotonic` برای کالیبراسیون مدل نهایی).

مجموعهٔ آزمون فقط یک‌بار ارزیابی می‌شود؛ فایل `outputs/models/test_set_used.lock` از اجرای دوباره جلوگیری می‌کند (`python run_all.py --force` برای رد کردن قفل).

گزارش LaTeX فارسی: `python src/generate_latex.py` ← پوشهٔ `report/` (با XeLaTeX کامپایل شود؛ پوشه مستقل و برای Overleaf آماده است).

## 5. روش‌شناسی

| بخش | تصمیم |
|---|---|
| ورودی | ستون‌های مجاز زمان پذیرش؛ بدون `ID`، پیامدها و ۹ ستون ممنوع |
| هدف مرگ | `LET_IS > 0` ← ۱، وگرنه ۰ |
| تقسیم | ۸۰/۲۰ با `stratify` روی مرگ، `random_state=42`؛ آزمون قفل |
| گمشدگی | حذف ستون‌های > ۵۰٪ گمشده (فقط از آموزش)؛ میانه برای پیوسته، مد برای دودویی/ترتیبی؛ همه داخل `Pipeline` |
| مقیاس | `StandardScaler` فقط برای رگرسیون لجستیک |
| مدل‌ها | `DummyClassifier(prior)`، `LogisticRegression` (L2)، RandomForest، XGBoost، LightGBM |
| تنظیم ابرپارامتر | `RandomizedSearchCV` با ۲۵ نمونه، معیار AUPRC، ۵-fold (`random_state=123`، جدا از foldهای گزارش) |
| گزارش CV | `StratifiedKFold(5, random_state=42)`؛ میانگین ± انحراف معیار foldها |
| انتخاب مدل نهایی | بیشترین AUPRC در جستجو؛ بدون وزن‌دهی و نمونه‌برداری مجدد |
| کالیبراسیون | `CalibratedClassifierCV(method="sigmoid")` (پلات)؛ ایزوتونیک و بتا برای مقایسه |
| آستانه | فقط روی احتمال‌های out-of-fold آموزش: کمترین آستانه با حساسیت ≥ ۸۰٪، و آستانهٔ هزینه‌محور `t* = C_FP/(C_FP + C_FN)` با نسبت ۱۰:۱ (مرگ) و ۳:۱ (دو پیامد دیگر) |
| معیارها | AUROC، AUPRC (و AUPRC/π)، Brier و BSS، Log loss، ECE، شیب/عرض از مبدأ کالیبراسیون، ماتریس درهم‌ریختگی، حساسیت، ویژگی، PPV، F1 (فقط کلاس مثبت) |
| تفسیر | SHAP (TreeExplainer) برای مرگ + تفسیر محلی دو بیمار |

### 6.3 آستانهٔ تصمیم

آستانه‌ها فقط روی دادهٔ آموزش انتخاب می‌شوند (`outputs/metrics/threshold_summary_oof.csv`، `outputs/models/thresholds.json`). راهبرد اصلی: کمترین آستانه با حساسیت ≥ ۸۰٪. راهبرد هزینه‌محور برای مرگ با نسبت هزینهٔ ۱۰:۱ برابر `t* = 1/11 ≈ 0.091` است. آستانهٔ ۰٫۵ برای پیامدهای نادر تقریباً همیشه نادرست است. جدول کامل (حساسیت، ویژگی، PPV، هشدار در هر ۱۰۰ بیمار): نوت‌بوک بخش ۴.

### سؤال ۲: احتمال پس از نمونه‌برداری مجدد

با `RandomUnderSampler(sampling_strategy=1.0)` داخل Pipeline، مدل از دادهٔ متوازن یاد می‌گیرد که شیوع ≈ ۵۰٪ است و احتمال مرگ را به‌شدت بیش‌برآورد می‌کند. دو اصلاح مقایسه شد:

1. **اصلاح احتمال پیشین:** `p = β·p_s / (β·p_s − p_s + 1)` با `β = n_pos / n_neg` دادهٔ آموزش هر fold؛ فقط اثر تغییر توزیع کلاس را جبران می‌کند.
2. **پلات روی دادهٔ جدا از آموزش** (`CalibratedClassifierCV`)؛ سایر خطاها (مثل شیب) را هم اصلاح می‌کند.

میانگین احتمال پیش‌بینی‌شده در برابر شیوع واقعی، Brier، ECE، شیب و عرض از مبدأ برای هر روش در `outputs/metrics/q2_undersampling.csv` و نمودار `outputs/figures/q2_undersampling_calibration.png` است (جدول در نوت‌بوک بخش ۷).

### سؤال ۳: آستانه با هزینهٔ ۱۰:۱

برای احتمال کالیبره، آستانهٔ بهینه `t* = C_FP/(C_FP + C_FN) = 1/(1+10) ≈ 0.091` است. اعداد «هشدار در ۱۰۰ بیمار»، «فوت شناسایی‌شده» و «فوت از دست‌رفته» روی احتمال‌های out-of-fold در `outputs/metrics/q3_threshold_cost10.csv` است. آستانهٔ پایین یعنی هشدارهای زیاد؛ این هزینهٔ منطقی ارزش ۱۰ برابری هر فوت است و PPV پایین می‌ماند.

### سؤال ۴: پیش‌بینی در برابر علیت

اهمیت بالای «مصرف هپارین در ICU» به این معنا نیست که هپارین باعث عارضه یا مرگ می‌شود:

- **تورش ناشی از اندیکاسیون (confounding by indication):** پزشک دارو را بر اساس وخامت بیمار تجویز می‌کند.
- **سوگیری بقا/زمان:** داروهای دورهٔ بستری فقط برای بیمارانی ثبت می‌شوند که تا آن لحظه زنده مانده‌اند.

## 8. سؤالات مقالهٔ انتخابی

مقالهٔ انتخابی: **Yavru & Yılmaz Gündüz (ESTUJST 2022)** — شبکهٔ عصبی برای ۱۲ خروجی؛ accuracy میانگین ۹۲٫۰۹٪ و sensitivity ۴٫۰۹٪.

**سؤال ۱ — sensitivity و specificity با مثال ۱۰۰ بیمار**

- Sensitivity = TP/(TP+FN): از بیمارانی که پیامد را دارند چه کسری پیدا می‌شود.
- Specificity = TN/(TN+FP): از بیمارانی که پیامد را ندارند چه کسری درست منفی تشخیص داده می‌شود.
- مثال: ۱۰ بیمار دچار عارضه و ۹۰ بیمار سالم. مدل ۶ نفر از ۱۰ بیمار را پیدا می‌کند (TP=6، FN=4) و از ۹۰ سالم، ۸۱ را درست منفی (TN=81) و ۹ را مثبت اشتباه (FP=9) می‌داند. آنگاه sensitivity = ۶۰٪، specificity = ۹۰٪ و accuracy = ۸۷٪. مدلی که همه را «منفی» بگوید accuracy = ۹۰٪ ولی sensitivity = ۰٪ دارد.

مثلاً وقتی سابقهٔ نارسایی مزمن (`ZSN_A`) ثبت نشده، ≈ ۹۱٪ بیماران فوت کرده‌اند. این الگوها احتمالاً از **فرایند ثبت** می‌آیند (مثلاً بیماری که زود فوت می‌کند سابقه‌اش ثبت نمی‌شود)، نه از زیست‌شناسی، و در استقرار واقعی ممکن است قابل استفاده نباشند. به همین دلیل مدل اصلی بدون شاخص گمشدگی است. اسکریپت `analyze_missingness.py` سازوکار را بررسی می‌کند (بلوک‌های هم‌زمان گمشده، و مدلی که فقط با شاخص‌های گمشدگی آموزش می‌بیند).

## 10. یافته‌های کلیدی و محدودیت‌ها

**یافته‌ها**

1. مدل مرگ در لحظهٔ پذیرش به AUROC ≈ ۰٫۸۹ (CV تودرتو ۰٫۸۹۱ ± ۰٫۰۱۲؛ آزمون ۰٫۸۸۷ با بازهٔ [۰٫۸۴، ۰٫۹۳]) و BSS ≈ ۰٫۳۸ می‌رسد.
2. اطلاعات ۷۲ ساعت اول چیزی به مدل پذیرش اضافه نمی‌کند.
3. نشت (SMOTE قبل از split) AUROC را از ≈ ۰٫۸۸ تا ≈ ۰٫۹۹ باد می‌کند.
4. مدل «همیشه منفی» به accuracy ≈ ۹۲٫۰۶٪ می‌رسد که با ۹۲٫۰۹٪ گزارش‌شدهٔ مقالهٔ Yavru تقریباً برابر است.
5. نارسایی مزمن قلب متوسط (AUROC ≈ ۰٫۷۴) و فیبریلاسیون دهلیزی ضعیف (AUROC ≈ ۰٫۶۹، BSS ≈ ۰٫۰۲) پیش‌بینی می‌شوند؛ تاکی‌کاردی فوق‌بطنی پیش‌بینی‌ناپذیر است.
6. پلات روی مدل‌های بوستینگ کمکی نمی‌کند؛ بتا (و برای مرگ ایزوتونیک) برابر یا بهتر است.
7. گمشدگی داده خودش حاوی اطلاعات پیامد است و می‌تواند عملکرد را مصنوعاً بالا ببرد.

**محدودیت‌ها**

- دیتاست کوچک، قدیمی و تک‌مرکزی است؛ اعتبارسنجی خارجی وجود ندارد.
- آزمون فقط ≈ ۵۴ فوت، ۸۸ ZSN و ۳۵ فیبریلاسیون دارد؛ بازه‌های اطمینان پهن‌اند.
- مقایسهٔ مستقیم با مقالات قبلی به‌دلیل تفاوت در هدف، زمان پیش‌بینی، تقسیم داده و معیار ممکن نیست؛ ادعای «بهتر از مقالات» پشتوانه ندارد.
- از بین سه آزمون مقایسهٔ DeLong (مدل نهایی در برابر رگرسیون لجستیک) پس از تصحیح بونفرونی هیچ‌کدام معنادار نمی‌ماند؛ برتری AUPRC برای مرگ و ZSN با bootstrap جفتی معنادار است.
- گمشدگی آگاهی‌دهنده ممکن است مصنوع فرایند ثبت باشد و باید با مستندات دیتاست راستی‌آزمایی شود.
